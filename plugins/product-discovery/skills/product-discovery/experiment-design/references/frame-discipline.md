# Frame Discipline

Before generating any concepts or experiments, write a one-sentence problem Frame.

## Rules

1. The Frame is ONE sentence. Not two. Not a paragraph.
2. The Frame describes the PROBLEM, never a solution.
3. The Frame names the USER and the SITUATION, not just the pain.
4. The Frame must be falsifiable - you could discover it's wrong.

## Good Frames

- "Home seekers on a property listing site need to decide fast whether a listing is real, relevant, and worth acting on, without being manipulated by fake urgency, stale listings, or missing context."
- "Small e-commerce merchants lose repeat customers because they can't identify who is about to churn until it's too late."
- "Junior PMs waste discovery cycles because they jump from a user complaint to a feature without understanding the opportunity space."

## Bad Frames (and why)

- "Users need a trust badge on listings." - This is a solution, not a problem.
- "The product has trust issues." - No user, no situation, not falsifiable.
- "We should improve the notification system." - Solution-biased, no user pain.
- "Users are frustrated." - Too vague. Which users? Frustrated about what? In what situation?

## How to Write It

Start with: "[User type] in [situation] cannot/struggle to [goal] because [obstacle]."

Then tighten it. Remove filler. Make every word load-bearing.

## When to Reject

If the Frame contains any of these words, it's probably solution-biased and should be rewritten: "need a", "should have", "add", "build", "implement", "create", "improve", "fix".
