# Product Sense Lenses (Optional Critique Pass)

After generating concepts, optionally run them through these 5 lenses to catch blind spots. Based on Shreyas Doshi's framework.

## The 5 Lenses

### 1. User Sense
"Does this solve a real problem for real people in a real situation?"
- Is the pain validated in the evidence matrix, or assumed?
- Would the user notice if this concept disappeared?
- Does this serve the primary user or an edge case?

### 2. Product Sense
"Does this make the product better as a whole, or just add a feature?"
- Does it fit the product's existing mental model, or create a new one users must learn?
- Does it create complexity that makes other features harder to use?
- Would a new user understand why this exists?

### 3. Business Sense
"Does this move a metric that matters, or just feel productive?"
- What business outcome does this drive? (retention, conversion, revenue, acquisition)
- Is the expected impact worth the opportunity cost?
- Could this backfire commercially? (e.g., transparency features that scare away supply-side users)

### 4. Tech Sense
"Can we actually build this, and can we maintain it?"
- Is the technical assumption the riskiest part? If so, test feasibility first.
- Does this require data we don't have access to?
- Does this create ongoing operational cost (manual processes, data pipelines, moderation)?

### 5. Craft Sense
"Is this the elegant version, or just the first version?"
- Is there a simpler way to achieve the same learning?
- Are we building the concept, or building the infrastructure to someday build the concept?
- Would a skilled practitioner look at this and say "why didn't you just..."?

## How to Apply

After presenting concepts in the bet-pack, add a brief critique section, e.g.:

"**Product Sense check:** Concept B (Duplicate Cluster) changes the search results mental model significantly - users expect individual listings, not grouped results. This is a usability risk worth testing early."

## When to Skip

This is optional. Skip it when:
- The concepts are straightforward and the risks are obvious
- The evidence is so strong that critique feels like delay
- The user asked for speed over rigor
